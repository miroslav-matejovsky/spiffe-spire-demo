Hands-on Scenarios

Use this page as a concept map and learning path. It is not a replacement for the scenario READMEs. Each scenario README has exact steps, expected output, and deeper notes for that environment.

Overview

This repository contains 7 progressive scenarios. Each builds on concepts from previous ones. Scenarios use Podman containers and stay self-contained so you can tear one down and move to the next without carrying state forward. While scenarios use Linux containers for portability, the SPIFFE and SPIRE concepts they teach apply directly to production deployments on Windows VMs, physical servers, and other traditional infrastructure.

Prerequisites

Complete the environment setup in Deployment before running any scenario. The helper scripts and binaries expect Podman, images, and local prerequisites to be ready first.

Running Scenarios

All scenarios follow the same flow. Build once, run one scenario at a time, and tear it down before starting another to avoid port and container-name conflicts.

task build
./bin/scenario-01-simple up
./bin/scenario-01-simple step
./bin/scenario-01-simple down
  • task build builds all Go helper binaries.
  • up starts the scenario.
  • step runs guided mode.
  • down tears the scenario down cleanly.
  • Only run one scenario at a time because host ports and container names overlap.
Containers vs production

These scenarios run SPIRE in Linux containers for easy setup and teardown. In production, SPIRE agents typically run as system services on Windows or Linux machines, and the SPIRE server runs centralized in a datacenter or cloud. The core concepts -- trust domains, attestation, SVIDs, workload registration -- remain the same regardless of deployment method.

Scenario Guides

01

Scenario 01 - Simple SPIRE Setup

Start with the smallest useful SPIRE deployment: one server and one agent. Focus on how a trust domain is defined and how an agent proves node identity with a join token.

Concepts Taught

Trust domains SPIFFE IDs Join token node attestation Basic server/agent

Components: spire-server, spire-agent

Key Learning Points

  • Understand trust domain concept and naming boundaries.
  • See join token flow from bootstrap to successful attestation.
  • Inspect agent and server logs for attestation events.
  • Verify the agent becomes attested and receives identity material.

Try It

task build
./bin/scenario-01-simple up
./bin/scenario-01-simple step
./bin/scenario-01-simple down

03

Scenario 03 - Workload Registration

Move from node identity to workload identity. You register a workload, match it with Unix selectors, and watch SPIRE issue and rotate an X.509 SVID.

Concepts Taught

Workload registration Unix workload attestor SVID issuance SVID lifecycle

Components: spire-server, spire-agent, dashboard, workload

Key Learning Points

  • Register a workload entry and connect it to selectors.
  • Understand why unix:uid selectors are enough for local workload identity.
  • Fetch an X.509 SVID from the Workload API.
  • Observe SVID rotation and see identity stay stable while certificates change.

04

Scenario 04 - Certificate-Based Attestation (TPM)

Replace join-token bootstrap with stronger certificate-based node identity ideas. This scenario introduces x509pop flow and the TPM DevID mindset used on more hardware-rooted systems, especially for VM and physical machine environments where cloud-provider metadata is not available.

Concepts Taught

x509pop attestation Certificate-based node identity Proof-of-possession TPM concepts

Components: spire-server, spire-agent, dashboard

Key Learning Points

  • Understand certificate-based attestation versus join token bootstrap.
  • See the x509pop flow and why proof-of-possession matters.
  • Learn how TPM DevID concepts fit stronger machine identity stories.
  • Compare operational tradeoffs between simple demos and stronger attestors.

Try It

task build
./bin/scenario-04-tpm up
./bin/scenario-04-tpm step
./bin/scenario-04-tpm down

05

Scenario 05 - SVID API (mTLS Services)

Apply SPIFFE identities in real services. Two Go workloads use go-spiffe, fetch SVIDs from the Workload API, establish mTLS automatically, and authorize by SPIFFE ID.

Concepts Taught

go-spiffe SDK mTLS Workload API Certificate rotation SPIFFE-ID-based authorization

Components: spire-server, spire-agent, dashboard, svid-server, svid-client

Key Learning Points

  • See Go services use go-spiffe instead of manual certificate handling.
  • Watch automatic mTLS setup happen from SPIFFE identities.
  • Inspect how SPIFFE IDs participate in the TLS handshake and authorization decision.
  • Observe zero-config certificate rotation through the Workload API.
  • Review UID selectors: svid-server=10001, svid-client=10002.
